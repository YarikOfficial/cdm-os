# ZachetOS / cdm-os

Учебная мини-операционная система для процессора **CdM-16** в **Logisim**.
Проект показывает базовые механизмы ОС: прерывания, драйверы устройств, shell, запуск программ, библиотечные функции, таймер и простой диспетчер фоновых задач.

## Что реализовано

- таблица векторов прерываний;
- обработчик клавиатуры;
- обработчик таймера;
- терминальный ввод/вывод через memory-mapped I/O;
- интерактивный shell с приглашением `>`;
- таблица программ: `имя команды -> адрес программы`;
- запуск пользовательских программ из shell;
- библиотечные функции для работы со строками и числами;
- программа `input` для проверки пользовательского ввода;
- программа `calc` для сложения двух чисел;
- простой диспетчер фоновых задач;
- команды мониторинга задач `ps` и `tasks`;
- защита shell от фоновых процессов.

## Команды shell

После запуска ОС пользователь вводит команды в терминале.

```text
count
adder
countbg
adderbg
kill1
kill2
ps
tasks
ls
input
calc
```

### Основные программы

| Команда | Назначение |
|---|---|
| `count` | Запускает первую тестовую программу в обычном режиме. |
| `adder` | Запускает вторую тестовую программу в обычном режиме. |
| `ls` | Показывает список доступных программ. |
| `input` | Запрашивает строку у пользователя и выводит её обратно. |
| `calc` | Запрашивает два числа, складывает их и выводит результат. |

Пример работы `calc`:

```text
>calc
a: 2
b: 3
result: 5
>
```

## Диспетчер фоновых задач

В системе реализован простой диспетчер задач. Он позволяет запускать программы в фоновом режиме, отслеживать их состояние и останавливать выполнение.

| Команда | Назначение |
|---|---|
| `countbg` | Запускает `count` как фоновую задачу. |
| `adderbg` | Запускает `adder` как фоновую задачу. |
| `kill1` | Останавливает фоновую задачу `count`. |
| `kill2` | Останавливает фоновую задачу `adder`. |
| `ps` | Показывает таблицу фоновых задач. |
| `tasks` | То же самое, что `ps`. |

Пример:

```text
>countbg
count started in background

>adderbg
adder started in background

>ps
PID NAME  STATE TICKS
1   count RUN   12
2   adder RUN   8

>kill1
count background stopped

>tasks
PID NAME  STATE TICKS
1   count STOP  12
2   adder RUN   15
```

### Как устроена диспетчеризация

Диспетчеризация выполнена кооперативно. Это значит, что фоновая задача не захватывает процессор навсегда, а выполняется маленькими шагами и сразу возвращает управление системе.

Общая схема:

```text
таймер
  ↓
обработчик таймера выставляет sched_tick_pending = 1
  ↓
shell просыпается после ожидания ввода
  ↓
вызывается task_dispatch_once
  ↓
диспетчер выбирает активную задачу
  ↓
выполняется один step фоновой программы
  ↓
управление возвращается shell
```

Для каждой фоновой задачи хранится:

- PID;
- имя программы;
- состояние `RUN` или `STOP`;
- счётчик выполненных тиков.

Выбор задач выполняется по простой схеме **round-robin**: диспетчер по очереди пытается обслужить `count`, затем `adder`, затем снова `count`.

Важно: это учебная реализация диспетчера фоновых задач, а не полноценная вытесняющая многозадачность. Для полноценного переключения процессов потребовались бы отдельные стеки, сохранение регистров, `PC`, `SP` и переключение контекста прямо в обработчике таймера.

## Защита shell от фоновых задач

Фоновые процессы не должны мешать пользователю работать в терминале. Поэтому в системе добавлены ограничения:

- фоновым задачам запрещён прямой вывод в терминал;
- фоновым задачам запрещено ждать ввод с клавиатуры;
- shell остаётся главным процессом, который управляет терминалом.

Для этого используется переменная `sched_current_task`:

```text
sched_current_task = 0  shell / обычная программа
sched_current_task = 1  фоновая задача count
sched_current_task = 2  фоновая задача adder
```

Драйвер терминала проверяет эту переменную перед печатью. Если код выполняется в фоне, вывод блокируется. Функция ввода строки также проверяет текущую задачу: если ввод пытается запросить фоновый процесс, функция сразу возвращает пустую строку и не блокирует shell.

## Архитектура проекта

Основные части системы:

```text
kernel_main.asm      — таблица прерываний, запуск ядра, обработчики клавиатуры и таймера, диспетчер задач
kernel_drivers.asm   — драйвер терминала и защита вывода от фоновых задач
os_main.asm          — главный цикл shell
os_lib.asm           — библиотечные функции: strcmp, gets, atoi, itoa
os_strings.asm       — строки ОС и программ
programs.asm         — таблица программ и код пользовательских программ
README.md            — описание проекта
```

### Interrupt Vector Table

В начале памяти находится таблица векторов прерываний. Через неё процессор получает адреса обработчиков:

- старт ядра;
- обработчик по умолчанию;
- обработчик клавиатуры;
- обработчик таймера;
- системный обработчик.

### Keyboard handler

Обработчик клавиатуры собирает строку ввода:

1. читает символ из порта клавиатуры;
2. сохраняет символ в `kb_buffer`;
3. обрабатывает `Enter`;
4. выставляет флаг `kb_line_ready`;
5. сбрасывает состояние клавиатуры через `kb_next`.

Он не запускает программы напрямую. Это важно, потому что ввод используется и shell, и пользовательскими программами.

### Timer handler

Обработчик таймера не выполняет фоновые программы напрямую. Он только увеличивает счётчик времени и выставляет флаг для диспетчера:

```text
sched_tick_pending = 1
```

Так обработчик остаётся коротким и безопасным.

### Shell loop

Главный цикл находится в `os_main.asm`:

1. включить терминал;
2. вывести приветствие;
3. вывести приглашение `>`;
4. прочитать строку через `os_lib_gets`;
5. найти команду в таблице программ;
6. выполнить найденную программу;
7. вернуться к ожиданию следующей команды.

### Таблица программ

В `programs.asm` хранится таблица команд:

```text
имя программы -> адрес кода программы
```

Shell сравнивает введённую строку с именами в таблице. Если команда найдена, управление передаётся соответствующей программе.

## Библиотечные функции

| Функция | Назначение |
|---|---|
| `os_lib_strcmp` | Сравнение двух нуль-терминированных строк. |
| `os_lib_gets` | Чтение строки пользователя. |
| `os_lib_atoi` | Перевод строки в число. |
| `os_lib_itoa_u16` | Перевод числа в строку. |

### `os_lib_gets`

```asm
r0 = адрес буфера назначения
r1 = максимальная длина буфера
jsr os_lib_gets
```

Функция ждёт нажатия `Enter`, копирует строку из клавиатурного буфера в буфер программы и завершает строку нулём.

## Memory-mapped I/O

Устройства подключены через фиксированные адреса памяти.

```text
0xF000 — порт символа клавиатуры
0xF002 — статус / управление клавиатурой
0xF008 — порт символа терминала
0xF00A — статус / управление терминалом
0xF010 — область таймера
```

## Сборка

Рекомендуемый способ установить ассемблер:

```bash
pipx install cdm-devkit
```

Сборка из папки `src`:

```bash
cd ~/cdm-os/src
cocas *.asm -t cdm16
```

Если команда `cocas` не находится, проверьте установку:

```bash
which cocas
pipx list
```

## Запуск в Logisim

1. Собрать проект через `cocas`.
2. Открыть схему в Logisim.
3. Загрузить полученный образ в RAM.
4. Запустить симуляцию.
5. Выбрать ввод с клавиатуры.
6. В терминале ввести команду, например:

```text
ls
countbg
ps
calc
```

## Цель проекта

Цель проекта — показать устройство простой учебной ОС для CdM-16:

- как работает ввод/вывод через драйверы;
- как обрабатываются прерывания;
- как shell запускает программы;
- как библиотечные функции используются разными программами;
- как таймер может быть основой для диспетчеризации;
- как реализовать простой диспетчер фоновых задач с мониторингом и защитой shell.
