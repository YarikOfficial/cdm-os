# Документация проекта ZachetOS / cdm-os

## 1. Термины и сокращения

**ОС** — операционная система.

**CdM-16** — учебная 16-битная архитектура процессора, используемая в проекте.

**Logisim** — среда моделирования цифровых схем, в которой запускается процессор, память и устройства ввода-вывода.

**Shell** — командная оболочка операционной системы. Принимает команды пользователя и запускает программы.

**Interrupt** — прерывание, сигнал от устройства или процессора, который временно останавливает основной код и передаёт управление обработчику.

**Timer interrupt** — прерывание от таймера. Используется для подсчёта системных тиков и запуска диспетчера задач.

**Memory-mapped I/O** — способ работы с устройствами через специальные адреса памяти.

**Task dispatcher** — диспетчер задач, который хранит состояние фоновых задач и управляет их выполнением.

**Background task** — фоновая задача, выполняющаяся без прямого вмешательства пользователя.

---

## 2. Введение

Проект **ZachetOS / cdm-os** представляет собой учебную мини-операционную систему для процессора **CdM-16**, работающую в среде **Logisim**.

Система написана на ассемблере CdM-16 и демонстрирует базовые механизмы операционных систем:

- запуск ядра;
- работу с прерываниями;
- ввод с клавиатуры;
- вывод в терминал;
- командную оболочку;
- запуск пользовательских программ;
- библиотечные функции;
- работу с таймером;
- простую диспетчеризацию фоновых задач.

После запуска ОС выводит приветственное сообщение, открывает терминал и ожидает команды пользователя. Пользователь может запускать программы, вводить данные, выполнять калькулятор, смотреть список доступных программ и управлять фоновыми задачами.

---

## 3. Цель, назначение и область применения

Цель проекта — разработать учебную мини-операционную систему для CdM-16, которая показывает основные принципы работы ОС на низком уровне.

Назначение проекта:

- показать работу таблицы векторов прерываний;
- реализовать обработку клавиатуры;
- реализовать вывод в терминал;
- создать простую командную оболочку shell;
- организовать запуск пользовательских программ;
- добавить библиотечные функции для работы со строками и числами;
- реализовать таймер;
- добавить простой диспетчер фоновых задач.

Область применения проекта — учебная демонстрация принципов работы операционных систем, архитектуры процессора, памяти, устройств ввода-вывода и низкоуровневого программирования.

---

## 4. Функциональные характеристики

Разработанная система поддерживает следующие возможности:

- вывод текста в терминал;

## 5. Технические характеристики

### 5.1. Общая архитектура системы

Проект состоит из нескольких основных частей:

- ядро ОС;
- драйверы устройств;
- библиотека функций;
- командная оболочка;
- таблица программ;
- пользовательские программы;
- диспетчер фоновых задач.

Основные файлы проекта:

| Файл | Назначение |

---

### 5.2. Таблица векторов прерываний

В начале памяти располагается таблица векторов прерываний. Через неё процессор получает адреса обработчиков.

Таблица используется для:

- запуска ядра;
- обработки неизвестных прерываний;
- обработки клавиатуры;
- обработки таймера;
- системных вызовов.

Такой подход похож на реальные операционные системы, где при прерывании процессор переходит не в случайное место памяти, а по заранее заданному адресу обработчика.

---

### 5.3. Работа клавиатуры

Клавиатура подключена через memory-mapped I/O. Это значит, что процессор работает с клавиатурой через специальные адреса памяти.

Обработчик клавиатурного прерывания выполняет следующие действия:

1. получает символ с клавиатуры;
2. сохраняет его в общий клавиатурный буфер;
3. проверяет, был ли нажат Enter;
4. если Enter нажат, выставляет флаг готовности строки;
5. сбрасывает состояние клавиатуры, чтобы можно было принять следующий символ.

Обработчик клавиатуры не запускает программы напрямую. Он только собирает строку ввода. Это важно, потому что ввод используется не только shell, но и пользовательскими программами.

---

### 5.4. Работа терминала

Терминал также работает через memory-mapped I/O.

Для вывода используется драйвер терминала. Он получает адрес строки, проходит по символам до нулевого байта и отправляет каждый символ в порт терминала.

Строки в системе являются нуль-терминированными. Это значит, что конец строки обозначается байтом `0`.

Пример логики вывода:

```text
взять символ строки
если символ равен 0 — завершить вывод
иначе отправить символ в терминал
перейти к следующему символу
```

---

### 5.5. Shell и запуск команд

Главный цикл shell находится в файле `os_main.asm`.

Логика работы shell:

1. включить терминал;
2. вывести приветствие;
3. вывести приглашение `>`;
4. прочитать команду пользователя;
5. найти команду в таблице программ;
6. запустить найденную программу;
7. снова вернуться к ожиданию команды.

Если пользователь вводит неизвестную команду, система выводит сообщение об ошибке.

---

### 5.6. Таблица программ

В `programs.asm` находится таблица программ. Она работает как простая файловая таблица.

Идея таблицы:

```text
имя программы -> адрес программы
```

Когда пользователь вводит команду, ОС сравнивает введённую строку с именами в таблице. Если имя найдено, ОС получает адрес программы и передаёт управление туда.

Такой подход позволяет добавлять новые программы без переписывания основного shell.

---

### 5.7. Библиотечные функции ОС

В файле `os_lib.asm` реализованы библиотечные функции.

Основные функции:

| Функция | Назначение |
|---|---|
| `os_lib_strcmp` | сравнение двух строк |
| `os_lib_gets` | ввод строки от пользователя |
| `os_lib_atoi` | перевод строки в число |
| `os_lib_itoa_u16` | перевод числа в строку |

Функция `os_lib_gets` используется как самим shell, так и пользовательскими программами. Она ждёт, пока пользователь введёт строку и нажмёт Enter, после чего копирует строку из общего клавиатурного буфера в буфер программы.

---

### 5.8. Таймер

Таймер используется как источник системных тиков.

Когда срабатывает таймерное прерывание, вызывается обработчик `tim_handler`. Он выполняет две основные операции:

1. увеличивает общий счётчик тиков;
2. выставляет флаг `sched_tick_pending`.

Таймер не запускает фоновые задачи напрямую. Это сделано специально, потому что обработчик прерывания должен быть коротким и безопасным.

Схема работы:

```text
таймер сработал
↓
обработчик таймера увеличил счётчик
↓
обработчик выставил флаг sched_tick_pending
↓
диспетчер позже обработал этот флаг
```

---

### 5.9. Диспетчер фоновых задач

В системе реализован простой диспетчер фоновых задач.

Он позволяет:

- запускать фоновые задачи;
- останавливать фоновые задачи;
- хранить состояние задач;
- считать количество тиков каждой задачи;
- показывать состояние задач пользователю.

Для каждой задачи хранится:

- PID;
- имя;
- состояние `RUN` или `STOP`;
- количество тиков.

Команды для запуска фоновых задач:

```text
prog1bg
prog2bg
```

Команды для остановки:

```text
kill1
kill2
```

Команды для просмотра состояния:

```text
ps
tasks
```

Диспетчеризация выполнена кооперативно. Это значит, что фоновая задача не выполняется бесконечно, а запускается маленькими шагами. На каждом шаге задача выполняет небольшой объём работы и сразу возвращает управление системе.

Пример:

```text
таймер сработал
↓
sched_tick_pending = 1
↓
shell проснулся после wait
↓
вызвался task_dispatch_once
↓
диспетчер запустил один step фоновой задачи
↓
управление вернулось shell
```

Это не полноценная вытесняющая многозадачность, как в Linux, Windows или macOS. В системе пока нет отдельного стека для каждого процесса, сохранения PC, SP и полного контекста процесса. Однако для учебной ОС реализована рабочая модель диспетчера фоновых задач.

---

### 5.10. Защита shell от фоновых задач

Фоновые задачи не должны мешать работе shell.

Проблема заключается в том, что фоновая задача могла бы начать писать в терминал или читать клавиатуру. Тогда она испортила бы ввод пользователя или украла бы символы из командной строки.

Для защиты используется переменная `sched_current_task`.

Если `sched_current_task = 0`, значит выполняется shell или обычная foreground-программа. В этом случае ввод и вывод разрешены.

Если `sched_current_task != 0`, значит выполняется фоновая задача. В этом случае вывод в терминал блокируется, а попытка чтения строки возвращает пустую строку.

Такой подход запрещает фоновым задачам напрямую влиять на работу shell.

## 6. Руководство пользователя

### 6.1. Требования для запуска

Для запуска проекта необходимы:

- macOS, Linux или Windows;
- установленный `cdm-devkit`;
- доступная команда `cocas`;
- Logisim с готовой схемой процессора CdM-16;
- исходные файлы проекта.

Проверить наличие `cocas` можно командой:

```bash
which cocas
```

Если команда установлена правильно, терминал покажет путь к программе.

---

### 6.2. Сборка проекта

Открыть терминал и перейти в папку проекта:

```bash
cd ~/cdm-os
```

Перейти в папку с исходниками:

```bash
cd src
```

Выполнить сборку:

```bash
cocas *.asm -t cdm16
```

После успешной сборки будет создан машинный образ программы, который нужно загрузить в память процессора в Logisim.

---

### 6.3. Запуск в Logisim

Порядок запуска:

1. Открыть схему проекта в Logisim.
2. Найти блок памяти RAM, в который загружается программа.
3. Нажать правой кнопкой мыши по памяти.
4. Выбрать пункт загрузки образа.
5. Указать файл, полученный после сборки через `cocas`.
6. Запустить симуляцию.
7. Включить тактирование процессора, если оно не включено.
8. Перейти к терминалу.
9. Вводить команды в поле клавиатуры/терминала.

В разных версиях Logisim пункт загрузки может называться по-разному:

```text
Load Image
Load Memory
Загрузить образ
Загрузить память
```

---

### 6.4. Работа с терминалом

После запуска ОС выводит приветствие и приглашение командной строки:

```text
>
```

После символа `>` пользователь вводит команду и нажимает Enter.

Пример:

```text
>ls
```

Если команда найдена, ОС запускает соответствующую программу. Если команда не найдена, выводится сообщение об ошибке.

---

### 6.5. Список команд

| Команда | Назначение |
|---|---|
| `ls` | вывести список доступных программ |
| `prog1` | запустить тестовую программу 1 в обычном режиме |
| `prog2` | запустить тестовую программу 2 в обычном режиме |
| `input` | проверить ввод строки от пользователя |
| `calc` | запустить простой калькулятор |
| `prog1bg` | запустить `prog1` как фоновую задачу |
| `prog2bg` | запустить `prog2` как фоновую задачу |
| `kill1` | остановить фоновую задачу `prog1` |
| `kill2` | остановить фоновую задачу `prog2` |
| `ps` | показать состояние фоновых задач |
| `tasks` | показать состояние фоновых задач |

---

### 6.6. Пример работы с программами

Команда `ls`:

```text
>ls
```

Программа `input`:

```text
>input

```

Программа `calc`:

```text

```

---

### 6.7. Демонстрация диспетчера задач

Запуск первой фоновой задачи:

```text
>prog1bg
prog1 started in background
```

Проверка состояния:

```text
>ps
PID NAME  STATE TICKS
1   prog1 RUN   5
2   prog2 STOP  0
```

Запуск второй фоновой задачи:

```text
>prog2bg
prog2 started in background
```

Проверка состояния:

```text
>tasks
PID NAME  STATE TICKS
1   prog1 RUN   12
2   prog2 RUN   8
```

Остановка первой задачи:

```text
>kill1
prog1 background stopped
```

Проверка:

```text
>ps
PID NAME  STATE TICKS
1   prog1 STOP  12
2   prog2 RUN   14
```

Так пользователь может запускать, останавливать и контролировать фоновые задачи.

---

### 6.8. Возможные ошибки и способы исправления

#### Ошибка: `zsh: command not found: cocas`

Причина: команда `cocas` не установлена или не добавлена в `PATH`.

Решение:

```bash
pipx install cdm-devkit
pipx ensurepath
```

После этого нужно перезапустить терминал и проверить:

```bash
which cocas
```

#### Команда в ОС не запускается

Возможные причины:

- команда не добавлена в таблицу программ;
- имя команды введено с ошибкой;
- после имени команды нет нулевого байта в таблице;
- адрес программы указан неверно.

#### Фоновая задача не увеличивает счётчик

Возможные причины:

- не запущен таймер;
- не вызывается `task_dispatch_once`;
- задача находится в состоянии `STOP`;
- неправильно подключена step-функция фоновой задачи.

#### В терминале нет вывода

Возможные причины:

- терминал не включён;
- образ не загружен в память;
- симуляция не запущена;
- программа находится в ожидании ввода.

## 8. Заключение

В ходе выполнения проекта была разработана учебная мини-операционная система для процессора CdM-16. В системе реализованы базовые компоненты ОС: таблица векторов прерываний, обработка клавиатуры, терминальный вывод, командная оболочка, таблица программ, библиотечные функции и пользовательские программы.

Дополнительно был реализован простой диспетчер фоновых задач. Он позволяет запускать задачи в фоне, останавливать их и просматривать состояние через команды `ps` и `tasks`.

Таймер используется как источник системных тиков, а диспетчер выполняет фоновые задачи маленькими шагами. Фоновые задачи не могут напрямую писать в терминал и читать клавиатуру, поэтому shell защищён от их влияния.

Проект демонстрирует основные принципы работы операционных систем и может быть расширен в будущем.

Возможные улучшения:

- полноценное сохранение контекста процессов;
- отдельный стек для каждой задачи;
- вытесняющая многозадачность;
- приоритеты задач;
